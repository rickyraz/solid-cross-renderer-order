Real three.js through @solidjs/universal

Each slot is a Mesh with an attached BoxGeometry, MeshBasicMaterial, and DataTexture. Swap them, change the box width (a constructor argument), or unmount them, and watch the WebGL memory counters.

Pointer events and raycasting

@solidjs/universal knows nothing about events. A prop like onClick reaches the renderer as an ordinary prop, so the renderer stores it, and a small event system does what the browser does for DOM elements:

  • Hit testing. Each pointer event casts one ray from the camera through the pointer, against the whole scene, nearest hit first.
  • Bubbling. The event goes from the hit mesh up through its parents. Clicking A also counts a click on the slots group. B calls stopPropagation(), so its clicks stay on B.
  • Hover. Only the nearest hit and its parents are hovered, like :hover. A hovered box turns yellow, because the handler writes a signal that drives the material's color prop.
  • Pointer capture. Press on a box and drag sideways to spin it. The box calls setPointerCapture(), so it keeps getting moves even when the pointer leaves it. The spin mutates rotation directly, without a signal.
  • Click means down and up on the same object. A drag from A to B is a click on neither, but their shared slots group gets one, as a DOM click goes to the common ancestor.
  • Disposal. When a hovered or captured box is unmounted, it is dropped without a pointerout: its owner is gone, so its handlers must not run. The component clears its own hover state with onCleanup.

Async loaders and shared resources

A second canvas, with its own WebGLRenderer, so its GPU counters stand alone. Each box waits for a texture from a slow loader. The left and middle boxes ask for the same texture, so they share one. The right box has its own.

  • Loading. The texture is read through an async createMemo. Until it arrives, Solid's <Loading> shows a wireframe box. The boundary works through the three renderer like any other component.
  • Shared resources. A reference-counted cache in plain JavaScript, with no Solid and no three, loads each key once. Hide the left box and the texture stays for the middle one. Hide both and the texture is disposed.
  • The old texture stays on screen. Click Next shared texture. In Solid 2, content that has rendered keeps showing while the new texture loads. A texture must not be released until its replacement is on screen.
  • Two release strategies. The Solid binding can release in the async memo's onCleanup (naive), or in the cleanup of an effect, which runs only once the replacement is committed (committed). I expected naive to dispose the texture on screen. It does not: in Solid 2.0.3, the onCleanup of the run on screen waits until its replacement lands. A run that never reached the screen is cleaned up at once. I found this behavior only by testing, not in the docs, so committed is the strategy to rely on.
  • Late disposal. Hide a box while its texture is still loading. When the texture arrives, nobody wants it, so the cache disposes it at once.
